SEBook Chrome profile sync

This extension copies cookies and localStorage from
https://tobiasduerschmid.github.io into your Chrome profile. After it is
installed, syncing is automatic.

Only the production HTTPS site is supported. Localhost, 127.0.0.1, other
ports, and other origins do not participate in profile sync.

Install
1. Unzip this archive. The folder inside is named sebook-chrome-profile-sync.
2. Open Chrome and go to chrome://extensions
3. Turn on Developer mode.
4. Choose Load unpacked and select the sebook-chrome-profile-sync folder.

Update
Replace the extracted folder with the latest archive, click Reload for
this extension at chrome://extensions, then reload any open site tabs.
Update every computer: version 1.0.3 upgrades the profile format to keep
older copies from rewriting it with page-supplied timestamps. Version
1.0.1 and 1.0.2 can still read the upgraded profile, but cannot upload
changes. Version 1.0.0 cannot read the origin-specific records.

Install the extension on each computer. Turn on Chrome profile sync and
sign in to the same Chrome profile. The site itself does not receive the
saved data. Chrome may store the profile copy with your Chrome account
when profile sync is on.

Do not save passwords or confidential code on the site if you use this
extension. Chrome profile sync holds about 100 kilobytes, so very large
tutorial files stay in the browser where they were saved. In-browser Linux
machine snapshots are not copied.

Private browsing does not write into the synced profile copy.

Upgrading from 1.0.0
Update the extension on every computer before using profile sync again.
Version 1.0.1 discards the old shared profile copy because it cannot tell
which site supplied those values. Data already saved in each site's
browser storage stays there; the production site's data seeds the new
origin-specific profile copy on its next visit. Older extension versions
cannot read or rewrite the new format, so update all installed copies.

Resource limits
Each sync snapshot accepts at most 1,024 entries, 1,024 UTF-8 bytes per
key, 256 KiB per value, 1 MiB of expanded JSON, and 128 retired-key rules.
A snapshot above these limits is rejected before merging; saved browser
data and the existing profile copy remain unchanged. Receiving profiles
accept at most 2,048 records and 2 MiB of expanded JSON, independently of
the compressed Chrome quota. An oversized or damaged profile copy is
reported as unreadable and is not overwritten automatically.
