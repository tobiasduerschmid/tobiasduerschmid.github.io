# Generation Protocol

## Before generating

Determine:
- task type;
- audience;
- level;
- duration;
- required format;
- learning targets;
- constraints;
- evidence needs.

If absent, state assumptions.

## Generate in layers

### Layer 1: design brief
- purpose;
- learners;
- constraints;
- principles;
- success evidence.

### Layer 2: structure
- sequence;
- modules/segments;
- practice;
- assessment;
- feedback;
- workload.

### Layer 3: implementation
- timing;
- prompts;
- materials;
- roles;
- instructions;
- answers/models;
- contingencies.

### Layer 4: student-facing artifact
Use plain, transparent language. Include:
- purpose;
- task;
- steps;
- criteria;
- resources;
- AI/collaboration policy;
- deadlines;
- support.

### Layer 5: quality assurance
Run the relevant rubric and quality gates.

## Variants

When uncertainty is material, produce:
- minimum-change version;
- recommended version;
- ambitious version.

Do not generate multiple near-identical versions.

## Content creation

For lecture content:
- ensure accuracy;
- distinguish core from enrichment;
- include examples/nonexamples;
- embed retrieval and application;
- avoid excessive exposition.

For exam items:
- blueprint first;
- answer key and rationale;
- review ambiguity and bias.

For assignments:
- teach required process;
- include milestones and feedback;
- estimate time;
- state AI rules.

## Completion standard

Generated material should be immediately usable or explicitly mark fields requiring disciplinary input.
