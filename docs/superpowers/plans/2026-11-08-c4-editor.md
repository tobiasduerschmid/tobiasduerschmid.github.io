# C4 Editor Implementation Plan (Milestone 3 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reusable, framework-free C4 editor (`ArchUMLC4Editor.mount`) that reads and writes `design.yml` through a host contract, with an outline, a navigable editable canvas, inspector forms, problems/review/explain/YAML panels, novice scaffolds, and full WCAG 2.2 AA keyboard and pointer access; plus the SEBook host adapter, inline embed, standalone editor page, and inventories.

**Architecture:** DOM-free state controller (`c4-editor-state.js`, Node-testable) drives focused DOM components (toolbar, outline, canvas, inspector, panels) mounted by `c4-editor-mount.js`. Every change is a core edit command producing text splices; the host persists text. The canvas uses `ArchUMLC4Render.renderView(…, {interactive: true})`, which emits an accessible listbox overlay. The site adapter (`js/c4-editor-site.js`) supplies host capabilities.

**Tech Stack:** Plain JavaScript UMD (no framework, no build), CSS custom properties and container queries, Playwright, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-08-c4-model-design.md` (sections 3.4, 7.3, 9, 10 are normative; for Tasks 13–16 also 4.11 and 9.5).

**Depends on:** Milestone 1 facade `ArchUMLC4` and Milestone 2 renderer `ArchUMLC4Render` and type registration. Tasks 13–16 also depend on Milestone 1b (`docs/superpowers/plans/2026-11-08-c4-interfaces.md`: interface edit commands, `usableInterfaces`, `interfacesOf`, `interfaceDependentsOf`) and rendering Tasks 9–12.

## Global Constraints

- Repository rules: never commit; WCAG 2.2 AA on every touched page; style ownership (no `style=`/page-local `<style>`; JS sets only computed values through the CSSOM); paragraph-size text everywhere (`font: inherit` on controls; secondary text ≥ 0.9em; never small `rem`); light, dark, and print coherent; print always light.
- The editor never touches `localStorage`, `sessionStorage`, cookies, `fetch`/XHR, `window.open`, or site globals; only the host does.
- Host contract exactly as spec §3.4, including `info = {reason, edits, version, label}`, echo suppression, host undo methods, `createSourceEditor` handle `{getValue, setValue, applyEdits, revealRange, setMarkers, focus, onDidChange, dispose}`, `sourceEditor`, `scaffolds`, `checks.display`, `reveal`, `lockedFields`, `palette`, `links`.
- Every control ≥ 24 × 24 CSS px; focus visible with site focus tokens; every focusable has `scroll-margin-block` (top ≥ navbar height 96px, bottom ≥ read-aloud bar).
- Keyboard: shortcut scope, Escape order, and focus table exactly as spec §9.2; DOM order toolbar → outline → canvas → inspector → panels at every width; no CSS reordering.
- All ids referenced by ARIA are prefixed per editor instance (several editors per page).
- Diagnostics text begins with "Error:", "Warning:", or "Suggestion:"; `aria-invalid` only for error-severity diagnostics on that field.
- Magnification uses the `--c4-zoom` custom property; the editor opens at 100%.
- Direct manipulation is the default (spec §9.2 table): dragging moves, connects, adds from the palette, refines from the carry-down tray, reorders lists, re-parents in the outline, and pans. Each drag has a single-pointer alternative (context menu "⋯"/right-click/long-press commands, click-then-click, collapsed Position controls) and a keyboard path; alternatives never add permanent clutter to the default view. Drags use Pointer Events, act on pointer up, cancel on Escape or an invalid drop, form one undo step, and announce their result.

## Review Focus

1. Two editors on one page (chapter "Try it" + practice embed): no shared ids, independent undo, independent Escape handling → test in Task 12.
2. Host text arriving while the user types in an inspector field (tutorial reset, VS Code edit): selection and focus survive, no echo loop → test in Task 2 and Task 10.
3. YAML syntax error typed in the YAML tab, then visual commands attempted → disabled with a reason, last valid model shown read-only → test in Task 10.
4. Screen-reader users must reach every edge, including derived edges, without a pointer → test in Task 8.
5. Narrow chapter column (≈ 700 px wide editor at 100–200% zoom): regions stack, toolbar wraps, nothing overflows except the canvas region → test in Task 4.
