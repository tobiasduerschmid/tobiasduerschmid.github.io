# C4 Core Library Implementation Plan (Milestone 1 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the DOM-free C4 + RDD design-model core in ArchUML: vendored YAML, schema, normalization, view projection, consistency checks, tutorial predicates, comment-preserving edits, text descriptions, UML text generation, facade, CLI, and JSON Schema.

**Architecture:** Hand-maintained UMD scripts under `js/ArchUML/c4/` (no build step), each usable as a classic browser script (`ArchUMLC4Parts.*`, facade `ArchUMLC4`) and through Node `require`. All edits are text splices against the original YAML; the document is never re-printed. Later milestones (renderer, editor, site, tutorial) consume only the facade.

**Tech Stack:** Plain JavaScript (ES2020 syntax, no `import`/`export`, no AMD), vendored `yaml` 2.9.1, Node 22 `node:test` + `node:assert/strict`, esbuild 0.25.12 (vendoring only).

**Spec:** `docs/superpowers/specs/2026-11-08-c4-model-design.md` (sections 3, 4, 5, 6.3, 7, 8 are normative for this plan).

## Global Constraints

- Repository rules: never commit (the user commits both repositories); no temporary files in the repo (scratch → the session scratchpad); stage nothing.
- Every core file uses the spec §3.1 UMD wrapper; no `define`/AMD branch; no access to `window`, `document`, timers, `Date.now`, or `Math.random`.
- YAML is parsed with `{schema: 'failsafe', keepSourceTokens: true, uniqueKeys: true}` and a `LineCounter`; edits are `{offset, length, text}` splices; whole-document printing is forbidden.
- Diagnostic shape: `{rule, severity, category, message, hint, element, path, range, fix}`; `severity ∈ {'error','warning','info'}`; `category` = rule id prefix before `/`; `range = {start: {line, col}, end: {line, col}}` 1-based, or `null`.
- Ids: `^[A-Za-z][A-Za-z0-9_-]*$`; schema version string `c4-design/1`.
- Rule ids, severities, and thresholds exactly as spec §7.2 (thresholds: 9 unrefined responsibilities, 7 collaborators, 20 view elements).
- Selector canonical form: lowercase plural keyword, single spaces, id exactly as declared (`containers of registration`); keywords match case-insensitively, ids case-sensitively.
- Tests live in `js/ArchUML/tests/c4/`, are named after behaviour, and assert spec values exactly.

## Review Focus

1. Windows line endings (CRLF) in `design.yml`: ranges and splices must keep `\r\n` intact → tests in Task 3 and Task 4.
2. Non-ASCII names and text (`Café`, `学生`): string offsets, slugs, and splices → tests in Task 2 and Task 3.
3. Four-space or mixed indentation in hand-written files: inserted lines must match sibling indentation → test in Task 4.
4. Empty, comment-only, or `schema:`-only documents: must yield an empty model without exceptions → test in Task 5.
5. A 300-element model: load, check, and project every view within a generous bound → test in Task 16.

### Task 3: `c4-yaml.js` — parsing, ranges, scalar splices
