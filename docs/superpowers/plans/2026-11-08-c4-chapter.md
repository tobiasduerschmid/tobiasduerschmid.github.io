# C4 Chapter Implementation Plan (Milestone 4 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `SEBook/architecture/c4.md`: a chapter that teaches why and how to use the C4 model, what each level and supplementary view captures, notation, and trade-offs, with Responsibility-Driven Design at every level, worked and faded examples rendered from one shared model, find-the-flaw figures, editor "Try it" embeds, a `## Interface Descriptions` section (objective 7: writing and reading interface descriptions, linked to the interoperability chapter), 13 quiz items, and 18 flashcards.

**Architecture:** Content in Markdown with `c4-view.html` figures (shared model files in `_includes/c4-models/`), inline ```` ```c4 ```` snippets for flawed or minimal examples, `c4-editor.html` embeds, and the standard quiz/flashcard includes. Alignment between objectives, activities, quiz items, flashcards, and tutorial steps is recorded in YAML comments and checked by a content test.

**Tech Stack:** Jekyll Markdown/Liquid, ArchUML `c4` type and editor (Milestones 2–3), jekyll-scholar, Playwright audits.

**Spec:** `docs/superpowers/specs/2026-11-08-c4-model-design.md` (sections 1, 2, 4.2, 4.11, 5.3, 6.6, 12 are normative; §12's objectives, outline, and `## Interface Descriptions` order are binding).

## Global Constraints

- Follow the project skills before writing: `sebook-authoring`, `pedagogical-advisor` (with `references/content-types/sebook-chapter.md` and `flashcards.md`), `quiz-format`, `good-diagrams`, `diagrams`, `wcag-aa-compliance`, `keyboard-glossary-tracker`.
- Nine H1s exactly as spec §12, short labels (the nav truncates at the first colon); sub-topics as `##`; no skipped heading levels; no `# References` (the layout adds it).
- Original prose only. No reproduction of Brown's or Mezzalira's text or diagrams; at most short attributed quotations. Adapted c4model.com definitions carry the CC BY 4.0 attribution line from spec §2.
- Write "C4 model" with lowercase "model" in prose (glossary term); logical punctuation outside quotation marks; no page-local styles.
- Every figure: a `# caption:` with context; flawed figures get authored descriptions (`description` parameter) that state the flaw-relevant absences neutrally.
- No answer leakage: commit-then-reveal uses `<details>` after a stated prediction prompt.
- Every student-facing artifact (prose, figures and captions, Quick Checks, quiz items with their `option_feedback`, flashcards) is aligned with the objective it serves using the `pedagogical-advisor` skill; learner-facing feedback never uses the word "misconception" (it explains the wrong reasoning instead).
- The chapter stays focused on C4: where a term means something else elsewhere (a UML «interface», a Docker container, a deployable component), one short definitional clause says so, with no separate section, table, or quiz item (user direction, spec §17).
- Do not modify `css/tutorial-print.css` (the user has uncommitted changes there).

## Review Focus

1. A reader on a 320 px phone in dark mode: every figure readable (paragraph-size labels), no horizontal page scroll, editor embeds stacked → audit in Task 8.
2. A screen-reader user doing the find-the-flaw activities: the text alternative must expose the same flaws → check in Task 4.
3. A CS130 student who never attended L04: nothing depends on the lecture; RDD is taught in the chapter → review in Task 3.
4. Print from a saved dark theme: light palette, figures within page width, Explain text for editor embeds → print audit in Task 8.
5. Quiz options shuffled at render time: no feedback refers to option positions → `scripts/check_quizzes.sh` in Task 6.
6. The interface card on a 320 px phone and in print: paragraph-size text, tables that scroll by keyboard instead of the page, every card line printed once in the light palette; the syntax-only card does not reveal the answer to its prediction → Tasks 4 and 8.
