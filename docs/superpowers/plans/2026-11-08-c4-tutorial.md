# C4 Tutorial Implementation Plan (Milestone 5 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tutorial backend `c4` that hosts the C4 editor on a `design.yml` tutorial file, grades steps with declarative `tests[].c4` predicates and model-aware hints, a nine-step C4 tutorial (spec §11) with solutions, seeds, alternative-model content tests, and audits, and the four-step follow-up tutorial "Describe an interface" (about 30 minutes, objective 7; decision D10).

**Architecture:** `js/tutorial-c4.js` installs backend methods on `TutorialCode` (AADL/TLA adapter pattern). `design.yml` is an ordinary tutorial file; the editor binds to its Monaco model with host undo and no internal YAML tab. Tests and hint conditions evaluate predicates through `ArchUMLC4.query` against a frozen snapshot.

**Tech Stack:** Tutorial runtime (`js/tutorial-code.js`), ArchUML C4 core and editor, Jekyll data files, Node `node:test`, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-08-c4-model-design.md` (sections 8 and 11 are normative; both step tables in §11 are binding; §4.2, §4.11, and §7.2 define the model and the interface rules the interface tutorial grades).

## Global Constraints

- Read `tutorial-authoring` (all sections it routes to for backends, tests, hints, page pairs, print), `cs-tutorial-design`, and `pedagogical-advisor` before starting; align every student-facing artifact (instructions, figures, hints, knowledge-check items and their `option_feedback`, explanations) with the objective it serves using `pedagogical-advisor`; update `tutorial-authoring` in the same change (backend, configuration, predicate vocabulary, hint condition).
- No new storage keys; `design.yml` uses the existing tutorial file persistence.
- Hints never give the target text; ladder orient → diagnose → scaffold; conditions use structural predicates. Learner-facing text never uses the word "misconception" (feedback explains the wrong reasoning instead) and writes "C4 model" in lowercase.
- Every step states what the checks cannot judge and has one reasoning check.
- Do not modify `css/tutorial-print.css` (the user has uncommitted changes there); if print needs a style, add it to a C4-specific stylesheet.
- WCAG 2.2 AA on the tutorial page and its print view in both themes.

## Review Focus

1. Reset and Show Solution while the editor has focus: text replaced, editor re-renders, focus lands sensibly, no echo → test in Task 1.
2. A stale test run (the learner edits during evaluation): results discarded → test in Task 2.
3. YAML errors at check time: tests show "?" with "Fix the YAML errors first", no authored or fallback hints appear (one "Fix the YAML errors first" card replaces them), controls return to idle → test in Tasks 2–3.
4. Learners who model the same design differently (renamed ids, synonyms, relationships declared one level deeper) still pass → content test in Task 6.
5. Keyword stuffing (the right words on the wrong element) fails → content test in Task 6.
6. Interface tutorial: ticking every Realizes box, writing the unit only in the meaning, or naming the whole interface instead of the operation fails, and every hint condition is reachable on a model whose test fails → content test in Task 6.
